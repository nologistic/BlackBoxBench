# Yuque Reproduction Feature Checklist (28 items)

Source: manually organized, 2026-08-27. Used to review an AI agent's reproduction of the Yuque workspace web app.

1. Multi-entry content creation orchestration: Home → new document / knowledge base / template / AI → different creation flows → the creation result enters the correct context
2. Document editing and persistence loop: create a document → edit the title/body → auto-save or manual save → leave → re-enter → content is preserved
3. Template instantiation and content isolation: Template center → choose a template → generate a document → modify the new document → the original template is unaffected
4. Knowledge base creation and initialization: create a knowledge base → configure information → visibility/type → create → automatically enter the knowledge base → content creation can continue
5. Quick note capture and publishing: enter instant content → Ctrl+Enter/button to publish → the new note appears → the input area resets → it still exists after a refresh
6. Knowledge hierarchy organization and navigation: user space → knowledge base → directory/grouping → document → return via the hierarchy path
7. Document ownership migration and path sync: a document belongs to knowledge base A → adjust its ownership → move it to knowledge base B → the home page/paths/search results update in sync
8. Behavior-driven content aggregation: read/edit/like/comment on a document → the corresponding content dynamically appears under the home "browsed/edited/liked/commented" sections
9. Multi-dimensional combined filtering: type → ownership → creator → combine conditions → delete a condition → the results are recomputed in real time
10. Global knowledge search and recall: enter keywords → search multiple knowledge objects → sort/filter → tap a result → locate the correct resource
11. Navigation-context and list-state restoration: set the tab/filter/scroll position → open a document → browser back → the original state is fully restored
12. Cross-system sync of like behavior: user B likes the document → the document's like state changes → the author's side receives the corresponding effect → B unlikes → it is undone in sync everywhere
13. Comment and @ collaboration loop: comment on a document → @ a user → the content is recorded → the mentioned user receives a message → tapping the message locates the corresponding discussion
14. Cross-type favorites aggregation: favorite documents/spreadsheets/other knowledge objects → unified presentation on the favorites page → tapping restores the original object
15. Favorite organization, sorting, and two-way state: favorite an object → sort by name/favorite time → unfavorite from the favorites page → the original object's favorite icon changes in sync
16. Business-event-driven notification generation: likes/comments/follows/system events occur → different notifications are generated by event type → they enter the corresponding category
17. Unread/read notification state machine: a new notification is produced → unread list → open the notification → the state becomes read → it can be found in the read tab
18. Notification categories linked with counts: counts are computed separately for all messages / likes / @comments / pending / system notifications, etc. → after a single item is read the counts in several places update in sync
19. "Mark all as read" batch state sync: unread items exist in multiple categories → tap mark all as read → all notifications update → the top badge, category numbers, and tabs refresh in sync
20. Actionable notifications and the access-request workflow: a user requests access to a private knowledge base → the Owner receives a pending item → view → approve/reject → permissions change → the applicant gets the result
21. Notification deep link and business-context restoration: tap a like/comment/access-request notification → jump to the specific document/knowledge base/approval page → the context is still preserved when returning to the message center
22. Garden public/private publishing state: Garden private → other users cannot access → the Owner sets it public → external access becomes visible → after disabling again it takes effect immediately
23. Selective curation of public knowledge content: many private knowledge bases → select some to add to the public garden → outsiders see only the published content → it disappears after removal
24. Profile and social-relationship aggregation: personal information + custom bio + following/followers + public knowledge bases + activity form the profile
25. Dynamic aggregation of creation data: create/edit documents and notes → metrics such as creation days, word count, and content updates are recomputed
26. Knowledge asset structure statistics: changes in documents/knowledge bases/notes → data such as "X documents / Y knowledge bases / Z notes" changes dynamically
27. Interaction data linked with author statistics: others read/like/comment/favorite → the author-side read count, like count, comment count, and interacting-user statistics update
28. Time-series creation index / heatmap: daily creation, editing, and publishing behavior → aggregate to dates → generate the annual activity heatmap → it is still correct after switching dates
29. Configuration, permissions, and runtime behavior linkage: modify message/reminder/permission settings → subsequent real business events follow the configuration
